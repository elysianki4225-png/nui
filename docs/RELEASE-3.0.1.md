# 3.0.1：表单可见性与交互修复

## 问题与修复

3.0.0 的 `.tf-input` 默认没有边框，依赖 `.tf-box` 提供边框，并隐藏占位文字以适配浮动标签。CAPTCHA 配置、新建/重命名文件夹、主题素材选择及部分公开资料字段未使用这个外层，导致输入功能存在，但空白控件看起来像没有输入框。

- 公共样式区分独立控件与浮动标签控件：独立 input/select/textarea 有完整边框、背景、内边距、可见占位文字和聚焦高亮，原有浮动标签表单不会出现双边框。
- 统一公开资料和优选配置的控件样式，保留手机 16px 输入字号，控制宽度不超过容器。
- CAPTCHA 标签与输入框分隔清晰；Site Key、Secret Key、域名提供输入提示，关闭拼写检查/自动大写并限制密钥长度。更换服务商或 Site Key 后，不再错误提示可以沿用旧 Secret。
- 保存按钮明确区分「验证配置并保存」和「保存（关闭验证）」。关闭仍只停用验证，不保存未验证的新密钥；安全行为没有放宽。
- 保存按钮前只保留关键提示，详细配置、隐私与 SSH 恢复说明可展开阅读，减少手机上查找保存按钮的滚动距离。
- 文件夹名称输入框增加明确提示。

## 验证

新增真实 Chromium 可见性检查，不再只检查控件存在或页面不溢出：

- 巡检 12 个管理页面当前显示的文本输入/下拉/多行文本控件边框和视口边界。
- CAPTCHA 在亮/暗主题及 320、360、768、1440px 下验证空字段、占位文字、焦点高亮、Tab 顺序和真实后端关闭保存。
- 验证用户文件夹弹窗与公开资料字段，保留原有鼠标/触摸拖动、加密、媒体与移动端回归。
- 将旧版 CSS 临时恢复后，新测试确实因不可见输入框失败；恢复修复后通过。
- 运行完整 `scripts/check-release.sh`，包含后端、存储、权限、安装升级、域名/NAT、UI、图像处理、浏览器和依赖审计。

本次没有数据格式或加密协议变更。更新部署后刷新页面；独立导出的 HTML 需要重新导出并替换。测试不等同于真实 Android/iOS 设备及实际 CAPTCHA、Cloudflare、Telegram 服务的线上验收，也不保证不存在其他未发现问题。
