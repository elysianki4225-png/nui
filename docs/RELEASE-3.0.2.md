# 3.0.2：人机验证失败诊断

## 本次解决的问题

3.0.1 将服务商拒绝、返回域名不匹配和验证动作不匹配合并为「人机验证未通过，请重新验证并检查域名配置」。这会让已经完成挑战的管理员反复修改域名，仍无法知道实际失败阶段。

本版改进可诊断性，**不宣称已经确定或修复特定线上 hCaptcha 失败的根因**。真实根因仍需更新后由服务商返回结果确认。

- 只有通过管理员认证的配置保存测试返回细分诊断。注册和两端登录不公开密钥配置细节。
- 使用固定白名单将服务商错误分类为 Secret 无效、Site Key/Secret 不匹配、Site Key 不匹配、令牌无效/过期、IP 参数错误等；未知返回给出明确的「服务商拒绝、原因未识别」。
- 区分「服务商成功但返回域名不符」与「服务商直接拒绝」，不再都建议改域名。Turnstile 动作不符单独提示。
- 正确读取服务商 HTTP 400 的结构化错误，不再一律当成网络失败；其他异常状态、无效 JSON、过大响应继续安全拒绝。
- 管理员测试区分服务端超时，并说明浏览器挑战成功不等于 VPS 服务端校验成功。
- 保存失败的文字与错误码常驻表单，可直接截图/复制，不必追赶瞬间消失的提示；保留输入内容便于修正。
- 不输出上游任意文本、返回域名、Secret 或令牌；响应限制、超时、重放保护、域名验证及成功前不启用配置的原则保持不变。

## 排查方式

更新后重新完成「验证配置并保存」，查看按钮下的错误码：

| 错误码 | 下一步 |
| --- | --- |
| CAPTCHA_SECRET_INVALID | 检查 Secret 是否完整、有效且属于对应账户 |
| CAPTCHA_KEY_MISMATCH | 核对 Site Key 与 Secret 的所属账户/适用范围 |
| CAPTCHA_SITEKEY_MISMATCH | 刷新页面并使用一致的 Site Key 重新挑战 |
| CAPTCHA_TOKEN_INVALID / CAPTCHA_TOKEN_EXPIRED | 重新生成挑战令牌，检查密钥配对；不要反复提交旧令牌 |
| CAPTCHA_HOSTNAME_MISMATCH | 服务商已报告成功，核对浏览器实际域名、服务商站点和本程序允许列表 |
| CAPTCHA_UPSTREAM_TIMEOUT / CAPTCHA_UNAVAILABLE | 检查 VPS 出站网络与服务商可达性，不要仅凭手机能打开挑战判断服务端网络 |
| CAPTCHA_PROVIDER_REJECTED | 未识别的拒绝原因，继续排查，不能认定只是域名配置错误 |

请勿在聊天、截图或命令行历史中公开 Secret/令牌。本更新不自动合并或部署到 VPS，也不取消失败时拒绝保存的安全检查。

## 验证

新增模拟服务商错误回归：管理员权限隔离、HTTP 400、未知/恶意错误文本过滤、无效/过大响应、域名/动作检查、失败不写入配置及 Secret/令牌不回显。真实 Chromium 回归覆盖持久错误提示、错误码、输入保留和不显示 Secret。完整发布套件包含此前各项安装、权限、存储、域名、UI 和加密回归。

这些测试使用模拟服务商响应；没有使用用户的 Secret，也未对其 VPS 或真实 hCaptcha 账户做远程校验。
