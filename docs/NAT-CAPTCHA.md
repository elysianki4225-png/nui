# NAT 部署与可选人机验证

## NAT：区分三个端口

- **访客端口**：浏览器访问的端口。直连 NAT 使用公网 HTTPS 映射端口；套 CF 时通常仍为 HTTPS 443。
- **公网映射端口**：服务商提供的入站端口。CF 的回源规则应指向这个端口。
- **机器内部监听端口**：Caddy 在 NAT 机器内监听的端口。服务商需将公网 TCP 转发至此。内部后端默认 127.0.0.1:8787，不应公开映射。

域名页用户/管理入口分别支持 NAT，默认关闭。开启后填写服务商给出的**入口公网 IP**、公网 HTTP/HTTPS 端口和内部 HTTP/HTTPS 端口。入口 IP 不一定等于 `curl ip.sb` 得到的出口 IP；未填写时不会用出口 IP 自动建议 DNS。DNS 的 A/AAAA 应指向真实入口。

### 直连示例

入口公网 `203.0.113.8`（文档示例，使用时替换），服务商映射：

- 公网 10080 → 机器内部 8080/TCP
- 公网 10443 → 机器内部 8443/TCP

访问 `https://memo.example.com:10443`，HTTP 入口重定向到这个地址。Caddy 只监听内部端口。NAT 直连不会自动下发 HSTS，避免浏览器将自定义 HTTP 端口原样升级成错误的 HTTPS 端口。曾经启用过 HSTS 的域名，请直接访问新 HTTPS 地址。

直连需要**浏览器信任且覆盖域名的证书和私钥**。可预先用 DNS-01 验证取得证书，不依赖入站 80/443。系统校验域名、有效期和私钥匹配，但不能替代客户端的证书链信任检查。**Cloudflare Origin CA 只用于 CF 回源，不能用于浏览器直连**。NAT 模式不会尝试自动签发；手动证书到期前需更换。

首次安装（从本仓库取得新版安装器后执行）：

```bash
sudo bash install.sh --domain memo.example.com --nat \
  --nat-public-ip YOUR_PUBLIC_IP \
  --nat-public-http-port 10080 --nat-public-https-port 10443 \
  --origin-http-port 8080 --origin-https-port 8443 \
  --tls-cert /path/fullchain.pem --tls-key /path/private.key
```

域名需提前解析，证书文件需已存在。安装器放行的是内部端口；服务商端口映射、云防火墙和 DNS 仍需自行配置。安装完成后访问输出的带端口网址设置管理员。

### NAT 前面套 CF

沿用上述映射，选择 Cloudflare：

- Flexible：CF SSL 设为 Flexible，回源规则目标端口为 **10080**；内部监听 **8080**。
- Full/Strict：CF 使用相同 SSL 模式，规则目标端口为 **10443**；内部监听 **8443**，安装对应回源证书。
- 浏览器仍访问 `https://memo.example.com`，不加内部/公网回源端口。

首次安装 Flexible 可使用上面的命令加 `--cloudflare`，不传证书参数；Full/Strict 需要提供回源证书并核对 CF SSL 模式。各域名的回源规则分别设置，以账户当前支持的规则能力为准。常见访客代理端口列表不等于自定义源站端口限制。

源站内部探测公网入口可能受 **NAT 回环**限制，需从其他网络验证。若服务商的映射使用 SNAT 隐藏源 IP，CF 节点识别和基于真实 IP 的风控可能不可靠；不要盲目开启「仅允许 CF IP」或自动封锁，也不要为了放行而信任任意客户端 IP 头。请先确认服务商是否保留源地址。

### 兼容与更新

普通非 NAT 部署仍使用原来的 80/443 行为；`--update` 保留现有域名、端口和证书配置。域名、静态管理入口、导出前端 API 地址均使用计算后的公网访问地址。修改公网 HTTPS 端口后，已导出的外部前端若使用旧 API 地址需要重新导出/更新；修改管理端不改变用户 API 地址。

## 人机验证

管理界面 → 风控 → 人机验证。独立于风控检测/自动封锁开关，默认关闭。

支持：Cloudflare Turnstile、Google **reCAPTCHA v2 复选框**、hCaptcha。不支持任意第三方验证 URL，防止错误配置或 SSRF。

1. 在所选服务商创建站点，加入用户域名、管理域名，以及实际使用的导出前端域名。
2. 输入公开 Site Key、对应 Secret Key，以及允许验证的域名（不含协议/端口）。
3. 打开启用开关，点击「验证配置并保存」，在**当前管理域名**完成一次验证。
4. 后端确认 Token、hostname、有效期（Turnstile 还检查 action）通过后才保存；失败保留旧配置。

开启后保护用户注册、用户登录、管理员登录。已有有效会话不受影响；已失效会话即使记住了密钥，也必须重新验证。不用于首次管理员初始化。网站切换域名之前请先同步服务商允许域名和这里的域名列表，或暂时关闭验证，防止新域名登录失败。

Secret 不回传公开配置、管理配置或通用设置接口，不写入审计消息；存于服务器受权限保护的元数据中，备份也应视为含密钥。用户凭据不发往验证服务；验证服务会收到 Token、网络信息等，其浏览器 SDK 属于引入的第三方代码，使用前应评估供应商信任与隐私条款。

服务器必须能够访问服务商 siteverify 地址，访客浏览器必须能加载相应 SDK/iframe；Google 服务在部分网络可能不可达。超时/服务异常不会绕过验证。Token 短时去重，校验并发最多 16，网络超时 8 秒，响应最多 16KiB。验证失败需重新取得 Token；重复、过期或不属于允许域名的 Token 不放行。

### 恢复访问

- 当前已登录管理员可直接关闭开关，不需要完成新验证码。关闭不会保存尚未验证的新密钥。
- 若所有管理员会话均失效，可通过现有 SSH `n-ui` 面板重置管理员凭据：本版本重置流程同时关闭人机验证并清除自动风控封锁；成功登录后重新配置并启用。
- 直接调用 `server/cli.js reset-admin` 仍须遵循既有流程：先停服务，以服务用户执行并保持文件权限，再启动；不要在服务运行时直接改写存储。

## 测试边界

本地测试覆盖三种服务商的协议适配（模拟响应）、服务端登录拦截、重放/域名/action/过期拒绝、密钥脱敏、启用前试验、管理员关闭及 SSH 恢复；Chromium 使用模拟 SDK 验证加载、CSP、取消与组件清理。真实验证码签发和服务商控制台配置未在本环境联调。

NAT 生成器、证书/端口冲突、访问 URL、安装参数和持久化有回归；CI 使用真实 Caddy 验证配置。服务商真实 NAT 映射、CF 回源规则、证书链和公网可达性需在部署环境确认，不声称已经自动开通这些外部资源。
