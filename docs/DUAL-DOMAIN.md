# 独立用户域名与管理域名

管理面板 → 域名：点击「用户界面」或「管理界面」，下方显示所选入口的完整配置。两端草稿分别保留，统一点击「应用更改」进行事务校验和保存。管理端启用「管理端使用独立配置」后拥有同样的 CDN、端口快选、证书、Token 验证、DNS 助手和回源诊断；默认继承模式仍兼容旧配置。用户端沿用原来的 CDN/SSL/端口设置；管理端可单独选择 CDN、SSL 模式、HTTP/HTTPS 回源端口、真实 IP 头和仅允许 CF 节点回源。

## 两个 Cloudflare 域名的示例

| 项目 | 用户端 | 管理端 |
| --- | --- | --- |
| 域名 | memo.example.com | manage.example.net |
| CDN | Cloudflare | Cloudflare |
| 回源 HTTP | 80 | 8080 |
| 回源 HTTPS | 443 | 8443 |
| SSL | Full (strict) | Full (strict) |
| 回源证书 | 覆盖用户域名 | 单独上传覆盖管理域名的证书/私钥 |

1. 两个域名的 A/AAAA 记录指向源站并开启代理。不同域名可以属于不同 Zone。
2. 分别在 CF 配置匹配的 SSL 模式。管理域名的 Origin Rule（回源规则）应将目标端口改为 8443；Flexible 则改为对应 HTTP 端口 8080。具体能力以当前 CF 账户提供的规则为准；如果不支持改写，使用常规回源端口，而不是假设填写端口后 CF 会自动跟随。
3. 浏览器仍使用 `https://manage.example.net`，不需要添加回源端口。访客访问端口、CF 回源端口、后端内部端口是三回事。
4. 在 VPS 和云平台防火墙放行需要的回源端口。应用程序不会自动修改 DNS、CF 规则或防火墙。启用仅 CF 回源时，直接通过公网源站测试会被拒绝，这是预期行为。
5. Full/Strict 管理端证书须在 CF Origin Server 等可信配置流程中另行生成，再上传对应 PEM 和私钥；也可以在管理界面的证书设置中填写该域名对应的 Cloudflare API Token 自动签发；两端 Token 独立，不互相复用。证书材料不写入公开设置或日志。
6. 检查预览和管理域名诊断后应用。保存前诊断反映现网配置，不证明尚未应用的新端口可达。服务可能短暂重载/重启，切换管理域名后需重新登录。保留 SSH，以便规则错误时恢复访问。

## 兼容性与安全边界

- 不填写管理域名：保持原来的用户域名 `/admin/` 入口。
- 填写管理域名但不启用独立配置：继承用户端 CDN/端口/证书。加密回源证书必须同时覆盖两个域名，否则拒绝应用；建议独立配置和独立证书。
- 只更改管理端不会更改用户域名、用户 API 地址或导出 Pages 配置。若同时更改用户域名，仍须更新外部引用。
- 同协议可在不同 Host 上共享端口；同一端口不可同时用于 HTTP 和 HTTPS，也不能占用后端内部端口。
- 一键安装的特权应用流程会检查证书有效期、域名覆盖和私钥匹配，校验 Caddy 配置，再重载。失败时恢复配置、代理文件和两套证书；回滚结果也会报告。CF 控制台/防火墙配置不在此事务范围内，不承诺外部网络始终可达或零中断。
- 没有特权应用能力的生产手动模式会拒绝启用独立管理回源，避免只更新后端而遗漏代理和证书。开发 inline 模式只用于本机测试，不会安装真实代理。
- `adminOrigin` 设置随 `domain.json`/主配置保存，正常升级复用。独立证书默认路径 `/etc/nui-memo/admin-origin.pem` 和 `admin-origin.key`，私钥为 `root:caddy`、0640；不要手工改成全员可读。

## 验证

`test/dual-domain.mjs` 覆盖双入口、继承、协议端口冲突、后端端口占用、真实 IP/HTTPS 策略、静态路由、API 和重启持久化。`test/dual-domain-cert.mjs` 使用 OpenSSL 生成真实证书检查 SAN/密钥和下游校验失败回滚（Caddy/systemctl 用隔离桩替代）。安装器测试检查升级保留独立证书与端口；DOM 和 Chromium 检查表单重绘不丢失证书草稿以及多尺寸无横向溢出。

本地测试不替代真实 VPS 上的 Caddy、ACME、CF Origin Rule 和防火墙联调。
