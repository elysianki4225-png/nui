# 3.1.1：拖动排序预览与方向修复

## 问题

旧实现直接克隆整个列表/网格条目作为拖动预览，再挂到 body。列表项的 `height:100%` 脱离虚拟列表行容器后变成接近视口高度；整套操作按钮也被复制到受限宽度内，挤压标题、时间和文件大小，导致手机上出现巨大面板和竖排文字。

此外，指针拖动始终插入目标之前，把某一项拖到紧邻的后一项可能看起来没有移动。正常结束拖动时的 lostpointercapture 也可能过早清除点击抑制标记。

## 修复

- 不再克隆整行。创建独立的 72px 高预览卡，仅包含缩略图/图标、标题、摘要，无按钮、选择框或排序标识。
- 标题/摘要保持单行省略；默认最大宽 280px，根据可见视口收缩，并将预览位置限制在屏幕内。
- 向后拖动（列表向下、网格向右/向下）插入目标之后，向前拖动插入目标之前；保留键盘排序和保存后的过渡动画。
- 正常释放指针捕获不再误清除点击抑制；取消、窗口失焦、页面隐藏、销毁监听器时清理预览/高亮/计时器。
- 活跃拖动期间忽略第二个指针，避免多指触摸互相覆盖。

## 验证

新增 Chromium 回归使用图片缩略图及长中英文文件名，覆盖列表/网格、320/360/768/1440px、鼠标/触摸：按住期间检查预览实际尺寸、位置、单行摘要及无操作按钮，验证向后插入和松手清理。原有真实加密文件夹排序、持久化、鼠标/触摸测试继续保留。jsdom 增补正常释放点击抑制和窗口失焦清理。

运行完整发布套件并重建导出模板。自动浏览器测试不等于所有手机实机验收；若有独立导出的 HTML，升级后需重新导出替换。本版不改变密文格式、门禁或存储配置。
