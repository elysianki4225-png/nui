# 3.1.0：用户端进入前验证

## 启用

管理端「风控 → 人机验证」：

1. 服务商选择 Cloudflare Turnstile，保持用户域名及管理域名配置正确。
2. 勾选「启用注册和两端登录的人机验证」。
3. 勾选新增的「用户端进入前验证（Turnstile，24 小时，IP 变化重新验证）」。
4. 点击「验证配置并保存」，完成真实配置校验后生效。

新增开关**默认关闭**，不会因升级突然拦截用户。只支持 Turnstile；切换其他服务商前需关闭该开关。此功能不是 Cloudflare CDN/WAF 的整站挑战，nip.io/直连部署也可使用现有 Turnstile 集成。

## 规则

- 首次打开用户界面，先检查访问通行，再恢复账号、读取本地密钥或渲染登录/备忘录页面。
- 未通过时显示独立访问验证界面并自动打开 Turnstile。取消、失败或无法检查权限时不能进入，可手动重试。
- 成功后发放最长 **24 小时**、绑定服务端识别到的客户端 IP 和验证配置版本的签名通行凭证。同 IP 下刷新/重新打开无需重复进站验证。
- 每次用户 API 请求都会检查；IP 改变、凭证过期或被篡改时返回 `ENTRY_REQUIRED`。页面可见时每 30 秒检查，回到前台、恢复网络/BFCache 时也检查。
- 重新验证时遮住用户界面，关闭私密弹窗、终止解密 Worker、清空内存中的密钥/解密缓存并释放媒体 URL。成功后重新载入页面恢复状态，不自动重发失败的保存/删除请求。
- 不增加指纹识别或额外风控触发规则。原有注册、登录、人机验证及风控封锁仍独立工作，进站通过不替代注册/登录验证。
- 管理端不使用此进站门禁，已有管理员会话可关闭配置。管理员查看公开头像/资料不受用户进站门禁影响。SSH 重置管理员会关闭人机验证，入口也随之停用。
- 存储迁移期间仍可完成访问验证和通过管理端关闭验证。

## 安全边界与使用提醒

- 通行不是登录身份，不能替代账号会话、解密密钥或原有权限检查。所有 `/api/user/`（含内容/缩略图）、公开资料/头像接口都受保护；管理员已认证的公开资料/头像读取例外。
- 普通站点使用 host-only、HttpOnly、SameSite=Strict Cookie，生产使用 Secure。导出前端因跨域使用独立 `X-Memo-Entry` 请求头，通行存于按 API 地址区分的 localStorage；需允许本地存储，并在后端配置正确的 CORS 白名单。
- 凭证包含过期时间、配置版本、带密钥的 IP 摘要和随机数，不包含原始 IP。签名密钥只在后端进程内存中，**服务重启会使所有通行失效**；验证配置变更也会失效。因此 24 小时是最长有效期，不保证重启后免验证。
- 此处的“同一浏览器”依靠浏览器保存的通行凭证识别，不采集指纹；复制凭证到相同出口 IP 的另一浏览器并不是账号认证，其他权限仍必须满足。
- 用户接口每次检查 IP，但已被服务器受理的请求不会因后续 IP 变化追溯撤销。未保存草稿在安全锁定时可能丢失；本版不将私密草稿另存明文到本地。
- 手机切换 Wi-Fi/流量、VPN 出口变化、IPv6 地址变化都可能重新验证。服务器无法无请求地实时探测 IP；隐藏页面恢复时检查，前台静置最长约 30 秒后检查。网络中断导致无法检查时暂停显示，不会无条件放行。
- **反向代理须正确传递可信客户端 IP，后端端口不应直接暴露公网**。沿用现有 clientIp/Caddy 配置；若代理只传共享出口 IP，则无法区分出口后的访客。勿通过盲信客户端自行提交的 IP 头“修复”识别问题。
- HTML/JS/CSS、公共配置和主题等启动资源仍可下载，以便显示验证页面。本功能不是流量清洗/WAF，也不能隐藏公共前端源码。
- 用户已选择保存在浏览器里的登录密钥不会因进站验证被删除；重新验证通过后可按原有记住登录逻辑恢复。没有记住密钥的用户可能需再次输入密钥。
- 不改变第三方验证码的隐私信任边界；启用前确认服务商条款，不公开 Secret。

## 验证

新增真实 HTTP 测试覆盖：24 小时过期、不同 IP、配置版本/重启失效、签名篡改、失败不发凭证、Cookie/header 两种传输、已有登录会话不能绕过、内容/缩略图类用户 API 保护、管理员恢复、CSRF、存储迁移及服务商限制。

新增 Chromium 回归覆盖：首次加载不提前恢复账号、取消仍阻断、通过后进入、导出模式请求头/刷新保持、模拟 IP 变化后清空私密界面及写请求不自动重发。完整发布套件继续覆盖此前功能。

验证码 SDK 和 siteverify 在新增自动测试中使用受控模拟，不等同于真实 Turnstile 或 VPS/NAT/代理环境的端到端验收。
