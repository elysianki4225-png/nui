# 3.0.3：Turnstile 显式渲染初始化修复

## 问题

前端以 `render=explicit` 加载 Turnstile，却在脚本加载完成后优先调用通用 `api.ready()`。Turnstile 在显式渲染模式下不支持该调用；异常发生在异步脚本加载事件中，没有被外部 Promise 捕获，原本的 15 秒计时器继续运行，最后错误地提示网络超时。

这与 VPS 是否在境外无关：错误出现在浏览器初始化 SDK 阶段，还没有提交服务端 siteverify 校验。

## 修复

- Turnstile 在脚本加载完成、确认 `render` API 可用后直接进入显式渲染，不调用 `turnstile.ready()`。
- Google reCAPTCHA 保留其 `ready()` 等待流程；hCaptcha 使用加载完成的渲染 API。
- 捕获脚本加载事件里的初始化异常，立即清理计时器和失败缓存，允许再次尝试，不再等到超时才掩盖真正原因。
- 区分 `CAPTCHA_SDK_INIT`（初始化异常）、`CAPTCHA_SDK_INVALID`（API 不完整）、`CAPTCHA_SDK_NETWORK`（加载失败）和 `CAPTCHA_SDK_TIMEOUT`（实际等待超时）。提示明确这是浏览器组件阶段，不是服务器校验阶段。
- 不延长超时掩盖错误、不代理第三方 SDK、不改变服务端验证或放行失败请求。

## 验证和边界

真实 Chromium 回归使用更贴近实际行为的 SDK 模拟：Turnstile 的 `ready()` 会抛错；修复后不调用它，正常获得挑战回调。另测试 Google 初始化抛错后立即返回诊断并可重试、hCaptcha 网络失败后可重试、三服务商适配、CSP、弹窗清理与取消后的迟到回调。

此前模拟 SDK 的 `ready()` 总是成功，未覆盖此不兼容行为；本版补足这一回归。完整发布套件继续覆盖安装、权限、存储、域名、加密和 UI。

没有使用用户真实密钥，没有访问其 VPS。真实网络阻断仍可能造成组件加载失败；此修复也不代表此前 hCaptcha 服务端校验失败已经解决。

## 更新

合并至 main 并部署更新后，确认后端版本为 3.0.3，再刷新管理页面。旧导出的独立 HTML 需重新导出替换。如果 Secret 曾出现在截图中，请先在服务商后台轮换，再在管理端输入新 Secret，勿再次公开。推送 PR 本身不等于合并或部署。
